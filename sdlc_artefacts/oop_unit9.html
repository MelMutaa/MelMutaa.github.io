Activity 1: Relevance of Cyclomatic Complexity in OOP Systems

Academic Perspective on Cyclomatic Complexity

How relevant is cyclomatic complexity in object-oriented systems?

Cyclomatic complexity remains relevant in object-oriented systems but requires careful interpretation when applied to OOP constructs. According to research by McCabe (1976) and subsequent studies:

Traditional Relevance

Control Flow Measurement: Cyclomatic complexity effectively measures the number of linearly independent paths through a program's source code.

Testing Guidance: Provides a lower bound on the number of test cases needed for branch coverage.

Maintainability Indicator: High complexity often correlates with difficult-to-maintain code.

OOP-Specific Considerations

Method-Level Analysis: Most effective when applied at the method level rather than class level.

Polymorphism Impact: Dynamic dispatch can make path analysis more challenging.

Inheritance Complexity: Does not account for complexity introduced by inheritance hierarchies.

Research-Based Limitations in OOP Context

  • Chidamber & Kemerer (1994): Found that cyclomatic complexity alone is insufficient for predicting fault-proneness in OO systems
  • Henderson-Sellers (1996): Argued that traditional metrics don't adequately capture OO concepts like encapsulation and polymorphism
  • Briand et al. (2000): Demonstrated that coupling and cohesion metrics often provide better fault prediction in OOP

Activity 2: Alternative Complexity Metrics

Which alternative metrics are more reflective of the complexity of a piece of code, in comparison to the number of independent paths through a program?

1. Maintainability Index

Definition: Composite metric combining cyclomatic complexity, lines of code, and Halstead volume

Advantage: Provides a more balanced view of code maintainability

Research Support: Coleman et al. (1994) demonstrated better correlation with maintenance effort

2. Cognitive Complexity

Definition: Measures how difficult code is to understand for humans

Advantage: Accounts for nested structures and complex boolean conditions

Research Support: Campbell (2018) showed better correlation with developer comprehension time

3. Weighted Methods per Class (WMC)

Definition: Sum of complexities of all methods in a class

Advantage: Specifically designed for OOP, considers class-level complexity

Research Support: Chidamber & Kemerer (1994) established WMC as a key OO metric

Metric Strengths in OOP Context Limitations Research Evidence
Cyclomatic Complexity Well-established, tool support, method-level analysis Ignores OOP features, class-level complexity McCabe (1976) - Original formulation
Maintainability Index Composite measure, practical maintenance prediction Can mask individual problem areas Coleman et al. (1994) - Empirical validation
Cognitive Complexity Human-centric, accounts for nesting and conditions Newer metric, less tool support Campbell (2018) - Comprehension studies
WMC OOP-specific, class-level analysis Depends on method complexity calculation Chidamber & Kemerer (1994) - OO metrics suite

Academic References Summary

  • McCabe, T. J. (1976): "A Complexity Measure" - Introduced cyclomatic complexity
  • Chidamber, S. R., & Kemerer, C. F. (1994): "A Metrics Suite for Object Oriented Design" - Established WMC and other OO metrics
  • Coleman, D. et al. (1994): "Using Metrics to Evaluate Software System Maintainability" - Developed Maintainability Index
  • Campbell, G. A. (2018): "Cognitive Complexity: A new way of measuring understandability" - Introduced cognitive complexity

Activity 3: Cyclomatic Complexity Calculation

Practical Analysis of Code Complexity

Cyclomatic Complexity Analysis

What is the cyclomatic complexity of the following piece of code?

public static string IntroducePerson(string name, int age)
{
    var response = $"Hi! My name is {name} and I'm {age} years old.";

    if (age >= 18)
        response += " I'm an adult.";

    if (name.Length > 7)
        response += " I have a long name.";

    return response;
}

Cyclomatic Complexity Calculation

Calculation Method

Formula: V(G) = E - N + 2P

  • E = Number of edges in the control flow graph
  • N = Number of nodes in the control flow graph
  • P = Number of connected components (usually 1)

Simplified Approach: V(G) = Number of decision points + 1

Decision Points Analysis

  1. First if statement: if (age >= 18) - 1 decision point
  2. Second if statement: if (name.Length > 7) - 1 decision point

Complexity Calculation

Number of decision points: 2

Cyclomatic Complexity: V(G) = 2 + 1 = 3

Control Flow Graph Representation

Start
  │
  ▼
Initialize response
  │
  ▼
if (age >= 18) ──True──▶ Append "adult" ───┐
  │False                                    │
  ▼                                         │
if (name.Length > 7) ─True──▶ Append "long name" ─┐
  │False                                         │
  ▼                                              │
Return response ◀────────────────────────────────┘

Complexity Interpretation

Complexity Range Risk Level Recommended Action
1-10 Low Simple procedure, low risk
11-20 Moderate More complex, consider review
21-50 High Complex, high risk - refactor needed
>50 Very High Untestable, must refactor

Assessment Result

Cyclomatic Complexity: 3 - This indicates a low complexity method that is easy to test and maintain.

Testing Requirements: Minimum of 3 test cases needed for full branch coverage.

Automated Complexity Analysis Tool

class ComplexityAnalyzer:
    """Tool for analyzing code complexity metrics."""
    
    @staticmethod
    def calculate_cyclomatic_complexity(code_lines):
        """
        Calculate cyclomatic complexity from code lines.
        Simplified implementation for demonstration.
        """
        complexity = 1  # Base complexity
        decision_keywords = ['if', 'while', 'for', 'case', 'catch', '&&', '||', '?']
        
        for line in code_lines:
            line_lower = line.lower().strip()
            # Count decision points
            for keyword in decision_keywords:
                if keyword in line_lower and not line_lower.startswith('//'):
                    # Simple keyword counting (real implementation would be more sophisticated)
                    if keyword in ['if', 'while', 'for', 'case', 'catch']:
                        complexity += 1
                    elif keyword in ['&&', '||']:
                        # Each logical operator adds a decision point
                        complexity += line_lower.count(keyword)
        
        return complexity
    
    def analyze_method_complexity(self, method_code):
        """Comprehensive complexity analysis."""
        lines = method_code.split('\n')
        cc = self.calculate_cyclomatic_complexity(lines)
        
        analysis = {
            'cyclomatic_complexity': cc,
            'risk_level': self._get_risk_level(cc),
            'test_cases_needed': cc,
            'recommendation': self._get_recommendation(cc)
        }
        
        return analysis
    
    def _get_risk_level(self, complexity):
        if complexity <= 10:
            return "Low"
        elif complexity <= 20:
            return "Moderate"
        elif complexity <= 50:
            return "High"
        else:
            return "Very High"
    
    def _get_recommendation(self, complexity):
        if complexity <= 10:
            return "No action needed - well-structured code"
        elif complexity <= 20:
            return "Consider code review for potential simplification"
        else:
            return "Refactor required - code is too complex"

# Test the analyzer
analyzer = ComplexityAnalyzer()
sample_code = """
public static string IntroducePerson(string name, int age)
{
    var response = $"Hi! My name is {name} and I'm {age} years old.";
    if (age >= 18)
        response += " I'm an adult.";
    if (name.Length > 7)
        response += " I have a long name.";
    return response;
}
"""

result = analyzer.analyze_method_complexity(sample_code)
print("Complexity Analysis Result:")
for key, value in result.items():
    print(f"{key}: {value}")

String Operations with Assertion Testing

Extend the following program to test accuracy of operations using the assert statement.

class StringOperations:
    """Enhanced string operations with comprehensive assertion testing."""
    
    def __init__(self):
        self.operations_log = []
    
    def concatenate_strings(self, str1, str2):
        """Concatenate two strings with validation."""
        # Input validation
        assert isinstance(str1, str), "First argument must be a string"
        assert isinstance(str2, str), "Second argument must be a string"
        
        result = str1 + str2
        
        # Result validation
        assert len(result) == len(str1) + len(str2), "Concatenation length mismatch"
        assert result.startswith(str1), "Result should start with first string"
        assert result.endswith(str2), "Result should end with second string"
        
        self.operations_log.append(f"Concatenated '{str1}' + '{str2}' = '{result}'")
        return result
    
    def repeat_string(self, text, times):
        """Repeat a string specified number of times."""
        # Input validation
        assert isinstance(text, str), "Text must be a string"
        assert isinstance(times, int), "Times must be an integer"
        assert times >= 0, "Times must be non-negative"
        
        result = text * times
        
        # Result validation
        if times == 0:
            assert result == "", "Zero repetitions should yield empty string"
        else:
            expected_length = len(text) * times
            assert len(result) == expected_length, f"Expected length {expected_length}, got {len(result)}"
            assert result.count(text) == times, f"Should contain {times} occurrences of '{text}'"
        
        self.operations_log.append(f"Repeated '{text}' {times} times = '{result}'")
        return result
    
    def string_length(self, text):
        """Calculate string length with validation."""
        assert isinstance(text, str), "Input must be a string"
        
        length = len(text)
        
        # Result validation
        assert length >= 0, "Length cannot be negative"
        assert length == sum(1 for _ in text), "Length calculation mismatch"
        
        self.operations_log.append(f"Length of '{text}' = {length}")
        return length
    
    def substring_extraction(self, text, start, end):
        """Extract substring with bounds checking."""
        assert isinstance(text, str), "Text must be a string"
        assert isinstance(start, int), "Start must be an integer"
        assert isinstance(end, int), "End must be an integer"
        assert 0 <= start <= len(text), "Start index out of bounds"
        assert 0 <= end <= len(text), "End index out of bounds"
        assert start <= end, "Start must be less than or equal to end"
        
        result = text[start:end]
        
        # Result validation
        assert len(result) == end - start, "Substring length mismatch"
        if start < len(text) and end > start:
            assert result in text, "Substring should be part of original text"
        
        self.operations_log.append(f"Substring of '{text}'[{start}:{end}] = '{result}'")
        return result
    
    def run_comprehensive_tests(self):
        """Run comprehensive test suite using assertions."""
        print("=== Running Comprehensive String Operation Tests ===")
        
        # Test concatenation
        try:
            result1 = self.concatenate_strings('Hello', 'World!')
            assert result1 == 'HelloWorld!', "Concatenation result incorrect"
            print("✓ Concatenation test passed")
        except AssertionError as e:
            print(f"✗ Concatenation test failed: {e}")
        
        # Test string repetition
        try:
            result2 = self.repeat_string('Hi', 3)
            assert result2 == 'HiHiHi', "Repetition result incorrect"
            print("✓ Repetition test passed")
        except AssertionError as e:
            print(f"✗ Repetition test failed: {e}")
        
        # Test edge cases
        try:
            result3 = self.repeat_string('Test', 0)
            assert result3 == '', "Zero repetition should yield empty string"
            print("✓ Edge case test passed")
        except AssertionError as e:
            print(f"✗ Edge case test failed: {e}")
        
        # Test length calculation
        try:
            length = self.string_length('Python')
            assert length == 6, "Length calculation incorrect"
            print("✓ Length calculation test passed")
        except AssertionError as e:
            print(f"✗ Length calculation test failed: {e}")
        
        # Test substring extraction
        try:
            substring = self.substring_extraction('Programming', 3, 7)
            assert substring == 'gram', "Substring extraction incorrect"
            print("✓ Substring extraction test passed")
        except AssertionError as e:
            print(f"✗ Substring extraction test failed: {e}")
        
        # Test error conditions
        try:
            self.concatenate_strings(123, 'text')  # Should raise AssertionError
            print("✗ Type validation test failed - should have raised error")
        except AssertionError:
            print("✓ Type validation test passed")
        
        print("\n=== Test Summary ===")
        print(f"Operations performed: {len(self.operations_log)}")
        for log_entry in self.operations_log:
            print(f"  - {log_entry}")

# Enhanced version of the original program with assertions
def demonstrate_string_operations():
    """Extended program with assertion testing."""
    str_ops = StringOperations()
    
    # Original operations with assertions
    str1 = 'Hello'
    str2 = 'World!'
    
    # using +
    result_concatenate = str_ops.concatenate_strings(str1, str2)
    print('str1 + str2 = ', result_concatenate)
    
    # using *
    result_repeat = str_ops.repeat_string(str1, 3)
    print('str1 * 3 =', result_repeat)
    
    # Additional operations with assertions
    length = str_ops.string_length(str1)
    print(f'Length of str1 = {length}')
    
    substring = str_ops.substring_extraction('Programming', 3, 7)
    print(f'Substring of "Programming"[3:7] = {substring}')
    
    # Run comprehensive tests
    print("\n" + "="*50)
    str_ops.run_comprehensive_tests()

if __name__ == "__main__":
    demonstrate_string_operations()

Assertion Testing Benefits

1. Defensive Programming

Input Validation: Assertions verify preconditions and catch invalid inputs early

Contract Enforcement: Ensures methods adhere to their specified contracts

2. Debugging Assistance

Immediate Feedback: Fail-fast approach identifies issues during development

Clear Error Messages: Descriptive assertions help pinpoint problems

3. Documentation

Code Intent: Assertions document expected behavior and constraints

Maintenance Aid: Help future developers understand code assumptions

Best Practices for Assertion Testing

Practice Implementation Benefit
Validate Inputs Check parameter types and ranges at method entry Prevents invalid data propagation
Check Postconditions Verify method results before returning Ensures correct output
Test Invariants Validate conditions that should always hold true Maintains system integrity
Use Descriptive Messages Provide clear error messages in assertions Faster debugging and understanding

Production vs Development Assertions

Development: Use assertions liberally for debugging and validation

Production: Consider performance impact; use exceptions for user-facing error handling

Python Note: Assertions can be disabled with -O flag, so don't rely on them for critical error handling
