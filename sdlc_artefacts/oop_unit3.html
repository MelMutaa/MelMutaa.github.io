Key Insights

  • Progressive Refinement: Models evolve from conceptual to implementation-specific
  • Multiple Views: Different stakeholders need different diagram types
  • Traceability: Maintain links between requirements, design, and implementation
  • Iterative Nature: In agile development, UML models are updated incrementally

State Machine Diagram — Washing Machine

Referencing "The Unified Modeling Language Reference Manual, 2nd Ed." — Fig. 3-7, Ch. 21

Brief

Using the State Machine Diagram in Figures 3-7 (Chapter 21), design a similar model for a washing machine. Identify states (e.g., Idle, Filling, Washing, Rinsing, Spinning, Completed), events (Start, DoorClosed, WaterLevelReached, TimerElapsed), guards (e.g., doorLocked), and actions (e.g., pumpOn(), motorStart()).

Example State Machine Structure (Based on UML Reference Manual)

[Initial] → [Idle] → [DoorClosed] → [Filling]
    ↓
[WaterLevelReached] → [Washing] → [TimerElapsed] → [Rinsing]
    ↓
[TimerElapsed] → [Spinning] → [TimerElapsed] → [Completed]
    ↓
[DoorOpened] → [Idle]

Composite State: WashingCycle
   ├── [PreWash] → [MainWash] → [Rinse]
   └── [Drain] (entry/exit actions)

Detailed Design Specifications

States Definition

  • Idle: Initial state, door unlocked, ready for input
  • Filling: Water inlet valve open, monitoring water level
  • Washing: Agitation motor active, detergent dispensed
  • Rinsing: Clean water cycles, removal of detergent
  • Spinning: High-speed rotation to remove water
  • Completed: Cycle finished, audible signal, door unlocked
  • Paused: User-interrupted state
  • Error: Fault detection state

Key Transitions & Guards

Transition Event Guard Condition Action
Idle → Filling startButtonPressed doorClosed == true lockDoor(), openWaterValve()
Filling → Washing waterLevelReached waterLevel >= requiredLevel closeWaterValve(), startAgitation()
Washing → Rinsing washTimerElapsed timer == 0 stopAgitation(), drainWater()
Any State → Paused pauseButtonPressed — storeCurrentState()
Any State → Error sensorFault — activateAlarm(), shutdownSystem()

Hints

  • Include an initial pseudostate → Idle.
  • Model composite states if you separate Wash into sub-states (Agitate/Soak).
  • Use internal transitions for timer ticks; use exit/entry actions for pumps/valves.
  • Model error/interrupt flows (e.g., DoorOpen triggers pause/abort).
  • Consider different washing programs (Quick, Delicate, Heavy Duty) as orthogonal regions
